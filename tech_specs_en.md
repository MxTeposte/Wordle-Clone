## 1. Overview

Wordkstate is a web app with daily guessing games in English and Spanish. The English version is available at **https://wordkstate.vercel.app/en**.

| Game | Internal ID | Tiles | Attempts | Alphabet |
|---|---|---|---|---|
| 5-letter word | `w5` | 5 | 6 | EN: A–Z · ES: A–Z + Ñ |
| 6-letter word | `w6` | 6 | 7 | EN: A–Z · ES: A–Z + Ñ |
| Hidden date (01/01/1900 → challenge day) | `date` | 8 digits | 10 | 0–9 |

- **Modes:** daily challenge (`daily`), where everyone gets the same answer that day, and practice (`practice`), with unlimited random games.
- **Design principles:**
  - **Hidden answer:** guesses are evaluated on the server, and the answer never reaches the browser until the game ends.
  - **No database:** the server is stateless; games and statistics live in the browser's `localStorage`.
  - **Reproducible lists:** word lists are generated by a script from open sources and committed to the repository.
  - **Vercel-ready:** Next.js with static pages, and Route Handlers running as serverless functions.

Central game definitions: [src/lib/games.ts](src/lib/games.ts).

## 5. Routes and rendering

### 5.1 Pages

Production URLs use the base **https://wordkstate.vercel.app**; for example, the English 5-letter game is at https://wordkstate.vercel.app/en/5.

| Route | File | Rendering | Content |
|---|---|---|---|
| `/` | `proxy.ts` | Proxy (307 redirect) | Redirects to `/en` or `/es` |
| `/en`, `/es` | `app/[lang]/page.tsx` | SSG | Game menu with today's status |
| `/en/5`, `/en/6`, `/en/date`, `/es/5`, `/es/6`, `/es/fecha` | `app/[lang]/[game]/page.tsx` | SSG (`dynamicParams = false`) | Daily challenge |
| `/en/{5,6,date}/practice` | `app/[lang]/[game]/practice/page.tsx` | Dynamic, on demand | English practice (`/es/.../practice` → 404) |
| `/es/{5,6,fecha}/practica` | `app/[lang]/[game]/practica/page.tsx` | Dynamic, on demand | Spanish practice (`/en/.../practica` → 404) |
| `/en/credits`, `/es/creditos` | `app/[lang]/credits`, `creditos` | SSG | Credits and licenses |
| Anything else | `app/[lang]/not-found.tsx` | — | Bilingual 404 |

- **Translated slugs:** defined by `GAMES[id].slug`, together with `PRACTICE_SLUG` and `CREDITS_SLUG`, in [src/lib/games.ts](src/lib/games.ts). `gamePath(lang, game, practice)` builds the URLs.
- **Static params:**
  - The `[lang]` layout generates `es` and `en`.
  - `[game]` generates each language's slugs top-down, via `gameStaticParams` in [src/server/pages.ts](src/server/pages.ts).
- **Route types:** `PageProps<'/…'>` and `LayoutProps<'/…'>` are generated by `next typegen`, which runs as part of `pnpm typecheck`.

### 5.2 Language selection (`proxy.ts`)

It only runs on `/` (`matcher: '/'`) and picks the language in this order:

1. **`wk_lang` cookie** (`es` | `en`). `rememberLang()` sets it when the user clicks the language switcher; it lasts 1 year, with `path=/` and `samesite=lax`.
2. **`Accept-Language` header**, sorted by `q`; the first `en*` or `es*` wins.
3. **Default:** `es`.

To open the English version directly, use **https://wordkstate.vercel.app/en**.

### 5.3 Metadata

- `<html lang>` set per language.
- `title` with the `%s · Wordkstate` template, a per-game `description`, `alternates.languages` (`/es`, `/en`) and Open Graph.
- `viewport.themeColor` for light and dark themes.

## 6. HTTP API

Three Route Handlers on the Node.js runtime. Shared behavior ([src/server/http.ts](src/server/http.ts)):

- **Method:** `POST` only, with a JSON body.
- **Maximum body size:** 4096 characters; a larger or malformed body is treated as `null` and returns `bad_request`.
- **Response header:** `Cache-Control: no-store`.
- **State:** none on the server. Everything needed travels in the request (date or token).
- **Errors:** `{ "error": "<code>" }` with HTTP 400.

| Error code | When |
|---|---|
| `bad_request` | Invalid body, unknown `game`/`lang`/`mode`, non-string guess or longer than 32 characters, unauthorized `reveal` |
| `invalid_date` | Daily challenge with an invalid `date`, before `START_DATE`, or more than ±1 day from the server's UTC date |
| `invalid_token` | Practice with a missing or tampered token, one encrypted with another secret, or one from another game |

### 6.1 `POST /api/guess`

Validates and evaluates a guess.

**Request**

| Field | Type | Required | Description |
|---|---|---|---|
| `game` | `"w5" \| "w6" \| "date"` | Yes | Game |
| `lang` | `"es" \| "en"` | Yes | Language |
| `mode` | `"daily" \| "practice"` | Yes | Mode |
| `date` | `"YYYY-MM-DD"` | In `daily` | The player's local date |
| `hints` | `boolean` | No (`daily`, date game) | Whether per-field arrows are returned |
| `token` | `string` | In `practice` | Game token |
| `guess` | `string` | Yes | Word (normalized) or date `YYYY-MM-DD` / `YYYYMMDD` |

```json
{ "game": "w5", "lang": "en", "mode": "daily", "date": "2026-09-15", "guess": "crane" }
{ "game": "date", "lang": "en", "mode": "daily", "date": "2026-09-15", "guess": "1969-07-20", "hints": true }
{ "game": "w6", "lang": "en", "mode": "practice", "token": "7vD7H-8UVN…", "guess": "planet" }
```

**200 responses**

```json
// Valid guess
{ "valid": true, "result": ["absent","present","correct","absent","absent"], "solved": false }

// Date with arrows (only if the game uses them)
{ "valid": true, "result": ["correct","correct","present","absent","correct","absent","correct","absent"],
  "hints": { "day": "up", "month": "down", "year": "equal" }, "solved": false }

// Rejected guess (does not use up an attempt)
{ "valid": false, "reason": "not_in_word_list" }
```

| `reason` | Game | Meaning |
|---|---|---|
| `not_in_word_list` | Words | Not in `allowed` |
| `wrong_length` | Words | Wrong length or characters outside the alphabet |
| `incomplete` | Date | Format other than `YYYY-MM-DD` |
| `invalid_date` | Date | The date does not exist (e.g. Feb 31) |
| `before_1900` | Date | Earlier than 1900-01-01 |
| `future_date` | Date | Later than the limit (the challenge `date` or the token's `createdOn`) |

- **`result`:** array with one value per tile (`correct` | `present` | `absent`).
- **Date game order:** always the canonical `YYYYMMDD`, whatever the language. The client reorders the tiles for display.
- **`hints`:** `up` means the real value is higher, `down` lower, and `equal` a match.

### 6.2 `POST /api/practice/new`

Creates a practice game.

**Request:** `{ "game": "w5", "lang": "en", "hints": false }`. `hints` only applies to the date game.

**200 response:** `{ "token": "<base64url>", "maxDate": "2026-09-15" }`

- **Words:** random index into the answer list for that language and length.
- **Date:** uniformly random date in `[1900-01-01, today UTC]`.
- **Randomness:** `crypto.getRandomValues`.

### 6.3 `POST /api/reveal`

Returns the answer for a **finished** game.

**Request:** the same identifying fields as `/api/guess` plus `guesses: string[]`.

**Conditions for a response** (otherwise returns `bad_request`):

- `guesses.length ≤ maxAttempts`.
- Every guess is valid.
- In addition, **one** of these holds:
  - one of the guesses is the answer;
  - **all** attempts were used.

**200 response:**

```json
{ "solution": "CRANE", "display": "CRANE", "puzzleNumber": 17 }
{ "solution": "ARBOL", "display": "ÁRBOL", "puzzleNumber": 17 }
{ "solution": "1969-07-20", "display": "1969-07-20" }
```

- **`display`:** for Spanish, the accented form, taken from `accents.json`.
- **`puzzleNumber`:** daily challenge only.

> The `reveal` check is intentionally lightweight: it prevents accidental spoilers, not cheating. Anyone who submits arbitrary valid guesses until the attempts run out gets the answer.

### 6.4 Implementation

| Function (`src/server/game-service.ts`) | Responsibility |
|---|---|
| `resolveGame(body, now)` | Validates `game`/`lang`/`mode` and the date or token, then computes the answer, `maxDate`, `dateHints` and `puzzleNumber` |
| `checkGuess(resolved, guess)` | Normalizes, validates against the dictionary or calendar, and evaluates |
| `createPractice(body, now)` | Generates the random reference and seals the token |
| `reveal(resolved, guesses)` | Checks that the game is over and returns the answer |
| `isAcceptableClientDate(date, start, now)` | ±1 day from UTC rule, and date ≥ `START_DATE` |

## 7. Game logic

### 7.1 Guess evaluation ([src/lib/evaluate.ts](src/lib/evaluate.ts))

The same two-pass algorithm is used for letters and digits:

1. Mark `correct` wherever the symbol matches in the same position. The remaining answer symbols are counted in a `symbol → remaining occurrences` map.
2. For each position that is not `correct`: if the symbol still has remaining occurrences, mark it `present` and decrement; otherwise `absent`.

This handles repeated letters correctly (`ABBEY/BABES`, `LLAMA/ALLAN`, `ANANAS/BANANA`) as well as repeated digits in dates. Symbols are split with `Array.from`, so `Ñ` counts as a single character.

### 7.2 Normalization ([src/lib/normalize.ts](src/lib/normalize.ts))

`normalizeWord`: uppercase → protect `Ñ` → NFD → strip combining marks (U+0300–U+036F) → restore `Ñ` → NFC.

- **Examples:** `árbol → ARBOL`, `pingüino → PINGUINO`, `niño → NIÑO`.
- **Where the same function is used:**
  - in the word-list pipeline;
  - in server-side validation;
  - on the physical keyboard (`normalizeKey`): typing `á` enters `A`.

### 7.3 Daily challenge

| Concept | Computation |
|---|---|
| Challenge date | The browser's **local** date (`todayLocal`), never before `START_DATE` |
| Server acceptance | `START_DATE ≤ date` and `|date − today UTC| ≤ 1 day` |
| `dayIndex` | `daysBetween(START_DATE, date)` |
| Challenge number | `dayIndex + 1` |
| Word answer | `shuffle(answers, seededRng(WORD_SEED, 'answers', lang, length))[dayIndex % answers.length]` |
| Date answer | `randomDate(seededRng(WORD_SEED, 'date', dayIndex), date)`, uniform in `[1900-01-01, date]`; **the same in both languages** |
| Day change | The client reloads the game when the tab becomes visible again (`visibilitychange`) or when the countdown reaches midnight |

**PRNG** ([src/lib/prng.ts](src/lib/prng.ts)):

- 32-bit seed: **FNV-1a** hash of the parts joined with `|`.
- Generator: **mulberry32**.
- Shuffle: deterministic **Fisher–Yates**.

The answer list is shuffled twice:

- **In the pipeline**, with the public seed `wordkstate-v1`.
- **On the server**, with the secret `WORD_SEED`. The result is cached in memory per language, length and seed. That is why reading the repository does not reveal the challenge order.

### 7.4 Date game ([src/lib/dates.ts](src/lib/dates.ts))

- **Representation:**
  - canonical `YYYY-MM-DD` (API and storage);
  - `YYYYMMDD` digits (evaluation);
  - display order per language (`DISPLAY_ORDER`): EN `MM DD YYYY` → `[4,5,6,7,0,1,2,3]`, ES `DD MM AAAA` → `[6,7,4,5,0,1,2,3]`.
- **Validation:** Gregorian calendar with 4/100/400 leap years (`checkDateGuess`), between 1900-01-01 and `maxDate`.
- **Validation while typing (`partialDateProblem`):** before submitting, it catches an impossible year prefix (`<19` or `>20`), a future year, a month above 12, a day above 31 and days that don't exist in that month.
- **Arrows (`dateHints`):** compare day, month and year separately.
  - Optional, and off by default.
  - Can only be changed before the first guess; that lock is enforced on the client.
  - **Daily challenge:** sent with each request as `hints`.
  - **Practice:** fixed inside the token. Changing them starts a new game.
- **Long format:** `Intl.DateTimeFormat` with `dateStyle: 'long'` and the UTC time zone.

### 7.5 Practice mode: tokens ([src/server/token.ts](src/server/token.ts))

| Aspect | Detail |
|---|---|
| Algorithm | AES-GCM (authenticated encryption), Web Crypto |
| Key | `SHA-256(GAME_SECRET)` imported as a 256-bit AES key (cached per secret) |
| IV | 12 random bytes per token |
| Format | `base64url(IV ‖ ciphertext+tag)` |
| Payload | `{ v: 1, game, lang, ref, createdOn, dateHints }` |
| `ref` | Index into `answers` (words) or ISO date (date game) |
| `createdOn` | UTC creation date: upper bound for valid dates in practice |
| Validation | Length 24–1024; any tampering or a different secret → `invalid_token` |

Rotating `GAME_SECRET` invalidates practice games in progress. The client shows "This game expired" and starts a new one automatically.

### 7.6 Hard mode ([src/lib/hard-mode.ts](src/lib/hard-mode.ts))

Word games only. Each guess must:

- place green letters in their positions;
- include yellow letters, respecting how many times they appear.

Validated **on the client only**. It can only be turned on before the first guess, and turned off at any time. The shared result marks it with `*`.

### 7.7 Sharing ([src/lib/share.ts](src/lib/share.ts))

```
Wordkstate 5 #17 4/6*          ← game, challenge number (or "(practice)"), attempts, * if hard mode
Wordkstate Date #17 7/10 ↕     ← ↕ if played with arrows; X/10 if lost

🟩⬛🟨⬛⬛
🟩🟩🟩🟩🟩
⬛⬛ 🟩🟨 🟩🟩🟩⬛              ← date: grouped by field in the language's display order
```

- **High-contrast colors:** 🟧 instead of 🟩 and 🟦 instead of 🟨.
- **How it is shared:**
  - on touch-pointer devices, `navigator.share`;
  - if unavailable or it fails, the text is copied to the clipboard;
  - as a last resort, the text is shown in a toast.

### 8.2 Download ([scripts/fetch-sources.ts](scripts/fetch-sources.ts))

- **Pinned URLs and SHA-256:** the script fails if a checksum does not match.
- **Download:** Node `fetch`.
- **Extraction:**
  - a custom *ustar* reader for the SCOWL `.tar.gz`;
  - `fflate.unzipSync` for `.oxt` (RLA-ES) and `.whl` (wordfreq).
- **Destination:** `data/raw/`, not committed.

### 8.3 Generation ([scripts/build-words.ts](scripts/build-words.ts))

**English**

1. Loads SCOWL's `english-words.NN` and `american-words.NN`, and assigns each word the lowest level it appears in.
2. **`allowed`:** `^[a-z]+$` words of level ≤ 80 and length 5 or 6.
3. **Answer candidates:**
   - level ≤ 50;
   - not a regular inflection (`isEnglishInflection` heuristic: `-s/-es/-ies`, `-ed/-ied`, `-ing`, `-est`, with doubled consonants);
   - Zipf ≥ 3.0.

**Spanish**

1. Expands the Hunspell dictionary with a custom expander ([scripts/lib/hunspell.ts](scripts/lib/hunspell.ts)). It supports:
   - `SFX`/`PFX` with conditions and `strip`;
   - prefix × suffix cross products;
   - two-level suffixes via continuation flags;
   - UTF-8 flags, including emoji with variation selectors.
2. Drops entries that aren't `^[a-záéíóúüñ]+$`: proper nouns, acronyms, symbols.
3. **`allowed`:** every expanded form, normalized.
4. **Answer candidates:** `.dic` stems only (singulars, infinitives, invariable words) with Zipf ≥ 3.0.
   - When variants look identical in play (`papa`/`papá`), the more frequent one wins.

**Shared**

- **Frequency:** wordfreq reader ([scripts/lib/wordfreq.ts](scripts/lib/wordfreq.ts)): gzip-compressed msgpack, `cB` format, `Zipf = 9 − index/100`.
- **Filters:** `data/blocklist.<lang>.txt` (hand-curated) and LDNOOBW.
- **Manual adjustments:**
  - `data/allowlist.<lang>.txt` forces answers;
  - `data/allowed-extra.<lang>.txt` adds valid guesses missing from the dictionary.
- **Selection:** up to 2,500 answers per list, ordered by frequency.
- **Shuffling:** with the `wordkstate-v1` seed.
- **Integrity:** the build fails if an answer is not in `allowed`.
- **Outputs:**
  - `src/words/<lang>/<len>/answers.json` (shuffled) and `allowed.json` (sorted alphabetically);
  - `src/words/es/accents.json` (`"ARBOL": "árbol"`);
  - `data/REPORT.md` with sizes, per-filter discards, samples and stems to review.

### 8.4 Current sizes

## 9. Persistence: where data is stored

### 9.1 Overview

| Data | Where | Written by | Lifetime |
|---|---|---|---|
| Daily game, in progress or finished | Browser `localStorage` | Client | 14 days (pruned) |
| Current practice game | `localStorage` | Client | Until a new one starts |
| Statistics (daily and practice) | `localStorage` | Client | Indefinite |
| Preferences (theme, contrast, hard mode, arrows) | `localStorage` | Client | Indefinite |
| "Has seen the rules" | `localStorage` | Client | Indefinite |
| Chosen language | `wk_lang` cookie | Client | 1 year |
| Answers, lists and secrets | Server (bundled JSON + environment variables) | Build / Vercel | — |

**Nothing is stored on the server:** no database, no sessions, no game logs.

Consequences:

- Statistics are **per browser and device**: they don't sync across devices and are lost if site data is cleared.
- If `localStorage` is unavailable (private mode, quota exceeded), the game still works but saves nothing. Reads and writes are wrapped in `try/catch`.

### 9.2 `localStorage` keys ([src/lib/storage.ts](src/lib/storage.ts))

| Key | Content |
|---|---|
| `wordkstate:prefs` | `Prefs` |
| `wordkstate:seen-help` | `true` |
| `wordkstate:w5:<lang>:daily:<YYYY-MM-DD>` | `SavedGame` (daily challenge, 5-letter word) |
| `wordkstate:w6:<lang>:daily:<YYYY-MM-DD>` | `SavedGame` (daily challenge, 6-letter word) |
| `wordkstate:date:daily:<YYYY-MM-DD>` | `SavedGame` (daily date challenge; **shared across languages**) |
| `wordkstate:w5:<lang>:practice` · `wordkstate:w6:<lang>:practice` | `SavedGame` (word practice) |
| `wordkstate:date:practice` | `SavedGame` (date practice) |
| `wordkstate:stats:w5:<lang>` · `wordkstate:stats:w6:<lang>` | Daily word `Stats` |
| `wordkstate:stats:date:plain` · `wordkstate:stats:date:hints` | Daily date `Stats`, without and with arrows |
| `wordkstate:stats:practice:w5:<lang>` · `wordkstate:stats:practice:w6:<lang>` | Word practice `Stats` |
| `wordkstate:stats:practice:date:plain` · `…:hints` | Date practice `Stats` |

**Pruning:** when a daily challenge loads, `pruneOldGames(today)` deletes `…:daily:<date>` keys older than 14 days. Statistics are never pruned.

### 9.3 Schemas

```ts
type Prefs = {
  theme: 'system' | 'light' | 'dark';
  highContrast: boolean;
  hardMode: boolean;
  dateHints: boolean;
};

type SavedGame = {
  guesses: { value: string; result: ('correct' | 'present' | 'absent')[]; hints?: DateHints }[];
  status: 'playing' | 'won' | 'lost';
  hardMode: boolean;        // set at the start (can be turned off)
  dateHints: boolean;       // set before the first guess
  token?: string;           // practice
  maxDate?: string;         // date limit (date game)
  solution?: string;        // display form, received from /api/reveal when the game ends
  puzzleNumber?: number;    // daily challenge
  statsRecorded?: boolean;  // prevents counting the same game twice
};

type Stats = {
  played: number;
  wins: number;
  currentStreak: number;
  maxStreak: number;
  distribution: number[];   // distribution[i] = wins in i+1 attempts (length = maxAttempts)
  lastDate?: string;        // daily challenge only
  lastWon?: boolean;
};
```

### 9.4 Statistics rules ([src/lib/stats.ts](src/lib/stats.ts))

| Rule | Daily challenge (`recordResult`) | Practice (`recordPracticeResult`) |
|---|---|---|
| When recorded | When the game ends (or on reload, if it wasn't recorded) | Same |
| Idempotency | By date (`lastDate`) and by `statsRecorded` | By `statsRecorded` |
| Streak | Wins on **consecutive days**; lost if a day is skipped (`visibleStreak`) | **Consecutive** wins; resets on every loss |
| Separation | Per game and language; the date game is split with/without arrows | Same, with a `practice:` prefix |

- **Attempt changes:** if `maxAttempts` changes (the date game went from 6 to 10), the stored distribution is extended and existing values are kept.
- **Statistics modal:** shows the current mode's statistics and says which in the subtitle, e.g. "Practice · 5-letter word · EN".

## 10. Frontend

### 10.1 Main components ([src/components/](src/components))

| Component | Responsibility |
|---|---|
| `GameScreen` | Game controller, detailed below |
| `Boards` (`WordBoard`, `DateBoard`) | Boards whose tile size is computed with CSS `min()`/`max()`/`calc()` over `100vw`/`100dvh`; Day/Month/Year labels and arrows |
| `Keyboards` (`LetterKeyboard`, `NumericKeyboard`, `keyStates`) | EN QWERTY, ES QWERTY with Ñ, compact numeric keypad; key state = best result seen |
| `GameMenu` | Game cards with today's status read from `localStorage` |
| `Dialogs` | `HelpDialog`, `StatsDialog`, `SettingsDialog`, `Countdown` to local midnight |
| `Modal` | `<dialog>` wrapper with `showModal()`; closes on Escape, backdrop or button |
| `Header` | Brand, help, statistics, settings and language switcher (sets the cookie) |
| `Toasts` | Temporary notices (`role="status"`, `aria-live="polite"`) |
| `PrefsProvider` | Preferences context; applies `data-theme` and `data-contrast` on `<html>` |
| `InlineScript` | Inline script that only executes from the initial HTML (see 10.3) |

**What `GameScreen` does:**

- loads or creates the game (daily or practice);
- handles physical and on-screen keyboard input;
- validates locally (length, hard mode, partial date) and calls the API;
- runs the reveal animations;
- when the game ends, fetches the answer, records statistics and opens the modal;
- handles sharing and the settings locks.

### 10.2 State

- **No state libraries:** `useState`/`useCallback`/`useMemo` and one context (`PrefsProvider`).
- **Physical keyboard:** a single `keydown` listener on `window`. It reads the latest handlers from a ref, and ignores keys with modifiers, while a modal is open, or while an input has focus.
- **Input lock:** while a request is in flight (`busy`) or a row is being revealed (`revealRow`).

### 10.3 Theme and pre-hydration flash

1. **Before React:** `InlineScript` in `<head>` reads `wordkstate:prefs` and applies `data-theme` (`light`/`dark`, resolving `system` via `prefers-color-scheme`) and `data-contrast="high"`. It runs while the HTML is parsed, before first paint.
   - It is a Client Component: it renders `type="text/javascript"` on the server and `text/plain` on the client, with `suppressHydrationWarning`.
   - This keeps React from warning *"Encountered a script tag…"* when the layout re-renders, e.g. on a language switch.
2. **In development:** `PrefsProvider` reapplies the attributes in `useLayoutEffect`. Strict Mode's remount clears them from `<html>`.
3. **Styles:**
   - CSS variables on `:root`, `[data-theme='dark']` and `[data-contrast='high']`;
   - Tailwind with `@custom-variant dark` keyed on `data-theme`.

### 10.4 Styles and animations ([app/globals.css](app/globals.css))

- **Variable-based palette:**
  - general: `--bg`, `--surface`, `--fg`, `--muted`, `--border`, `--accent`, `--key-bg`;
  - results: `--correct`, `--present`, `--absent`;
  - high contrast: orange `#f5793a` and blue `#3d8fd6`.
- **Animations:**
  - `tile-flip`: a flip that changes color halfway, staggered per tile with `--delay` (280 ms for words, 160 ms for dates);
  - `tile-pop` when typing;
  - `row-shake` on an invalid guess;
  - `tile-bounce` on a win;
  - `modal-in` when a modal opens.
- **Reduced motion:** `prefers-reduced-motion: reduce` disables all animations.

### 10.5 Internationalization ([src/i18n/](src/i18n))

- **Dictionaries:** TypeScript objects. `es.ts` defines the `Dictionary` type and `en.ts` must satisfy it, so a missing key breaks the build.
- **Parameterized strings:** functions, e.g. `description(n)`, `hardGreen(pos, letter)`, `daily(n)`.
- **Game descriptions:** receive `maxAttempts`, so they always match `GAMES`.
- **No i18n library:** the language comes from the URL segment (`/en`, `/es`).

### 10.6 Accessibility

- **Tiles:** `role="img"` with an `aria-label` ("A, correct").
- **Rows:** `role="group"` ("Guess 3").
- **Results:** after each guess, an announcement in a visually hidden `aria-live` region.
- **Modals and settings:** native `<dialog>` elements with a title (`aria-labelledby`); `role="switch"` toggles; visible focus.
- **Icon keys:** buttons with an `aria-label` ("Delete", "Statistics"…).

## 12. Security

| Measure | Detail |
|---|---|
| Answer kept off the client | Pages and JavaScript contain no answers; the API only reveals them when the game ends |
| Unpredictable order | Shuffled with the secret `WORD_SEED`; the public repository doesn't reveal upcoming challenges |
| Practice tokens | AES-GCM: confidentiality (the answer can't be read) and integrity (tokens can't be altered) |
| Future dates | The server rejects client dates more than ±1 day from UTC, so future challenges can't be requested |
| Bounded input | Body ≤ 4 KB; guess ≤ 32 characters; strict enum validation |
| Previews | Preview deployment protection on Vercel and secrets different from production |
| No personal data | No accounts, analytics or server-side storage |

**Accepted risks**

- `/api/reveal` can be used by submitting arbitrary valid guesses until the attempts run out.
- Hard mode and the daily arrows lock are enforced on the client only.
- There is no rate limiting yet. It is planned via Vercel Firewall.
